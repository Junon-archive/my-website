# Content keys (en.json) → pages

Generated by hand from `lang/en.json` after the Phase 1 rewrite. 349 keys.
Every value is plain text: no HTML, no markup, no line breaks. `kr.json` and `jp.json` must
carry the identical key set; `detail_*`, `work_*` and `resume_*` item values are the same English.

Rules that implementers should not have to guess:

- Card date, badges, tags, role, period, stack, artifacts, charts and evidence come from
  `assets/js/works-data.js`, **not** from lang keys.
- Section headings on detail pages come from `detail_common_p_s1..s7` (projects) and
  `detail_common_r_s1..s7` (research). Sections that a work does not have are dropped from the
  HTML and the remaining numbers move up, so `#s5` is not always "What went wrong".
- Diagram captions are `detail_<id>_fig_<name>`; the `<name>` values and their target section
  are listed in `works-data.diagrams`.
