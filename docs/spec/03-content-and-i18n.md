# 03. 콘텐츠 데이터 모델과 번역 (Content & i18n)

## 1. 소스 오브 트루스

| 데이터 | 소스 | 파생 | 검증 |
|---|---|---|---|
| UI 문자열, 상세 본문 | `lang/en.json`, `lang/kr.json`, `lang/jp.json` | `assets/js/lang-data.js` (스크립트 생성) | `scripts/check.mjs` |
| 작업 목록(카드, 정렬, 메타, 링크) | `assets/js/works-data.js` | 없음 (런타임 렌더) | `scripts/check.mjs` |
| 이력서 항목 | `lang/*.json` (`resume_*`) + works-data(프로젝트 목록) | | |
| 프로필/연락처 | `lang/*.json` (`profile_*`, `contact_*`) | | |

`lang-data.js`는 손으로 편집하지 않는다. 파일 상단에 `/* GENERATED by scripts/build-lang-data.mjs. Do not edit. */`를 넣는다. 커밋은 한다(빌드 없는 배포를 위해).

## 2. 번역 로딩 동작 (`lang.js`)

1. `lang-data.js`가 동기 로드되어 `window.TRANSLATION_DATA` 제공. 첫 렌더는 여기서.
2. `lang.js`가 `lang/<lang>.json`을 fetch해 성공하면 교체. 실패하면 조용히 유지. (현행과 같음. 단, JSON과 lang-data가 생성 관계이므로 내용이 같아 깜빡임 없음)
3. 키 조회 순서: 현재 언어 → `en` → HTML 기본 텍스트.
4. `data-lang` 요소는 `textContent`로 채운다. HTML을 넣어야 하는 키는 없어야 한다. 줄바꿈이 필요하면 요소를 나눈다.
5. `data-placeholder`, `data-lang-attr="aria-label"` 등 속성 대상 지원. 폼이 사라지므로 placeholder는 실제로는 미사용이지만 기능은 유지.
6. `html[lang]`은 `kr→ko`, `jp→ja`, `en→en`으로 설정한다(현행은 `kr`, `jp`를 그대로 넣어 잘못됨).

## 3. 키 규약

형식: `<scope>_<id>_<field>[_<n>]`. 소문자와 밑줄만.

| scope | 설명 | 예 |
|---|---|---|
| `nav_` | 헤더 링크 | `nav_home` |
| `brand_` | 브랜드 | `brand_name` |
| `hero_` | Home 히어로 | `hero_eyebrow`, `hero_name_native`, `hero_name_latin`, `hero_role`, `hero_areas`, `hero_lead`, `hero_cta_research`, `hero_cta_projects`, `hero_cta_cv` |
| `pill_` | 가치 제안 4개 | `pill_1_title`, `pill_1_desc` … `pill_4_desc` |
| `home_` | Home 섹션 헤드 | `home_research_title`, `home_research_sub`, `home_research_more`, `home_projects_title`, `home_projects_sub`, `home_projects_more` |
| `portfolio_` | Portfolio | `portfolio_eyebrow`, `portfolio_title`, `portfolio_sub`, `filter_all`, `filter_projects`, `filter_research` |
| `work_<id>_` | 카드 문자열 | `work_ebpf_title`, `work_ebpf_sub` (date는 works-data로 이동, 키 삭제) |
| `detail_<id>_` | 상세 본문 (영어 단일, kr/jp는 en과 동일 값) | 05 문서의 필드 목록 |
| `detail_common_` | 상세 공통 라벨 | `detail_common_contents`, `detail_common_back`, `detail_common_role`, `detail_common_period`, `detail_common_stack`, `detail_common_artifacts`, `detail_common_prev`, `detail_common_next`, `detail_common_updated` |
| `badge_` | 배지 텍스트 | `badge_project`, `badge_research`, `badge_progress`, `badge_done` |
| `resume_` | 이력서 | 아래 4절 |
| `contact_` | 연락처 | `contact_eyebrow`, `contact_title`, `contact_email_label`, `contact_email_note`, `contact_github_label`, `contact_github_note`, `contact_lab_label`, `contact_lab_name`, `contact_lab_addr`, `contact_open_label`, `contact_open_desc` |
| `footer_` | 푸터 | `footer_quote`, `footer_affiliation`, `footer_copyright` (연도 제외 "Junheon Lee") |
| `meta_` | SEO | `meta_desc_home`, `meta_desc_portfolio`, `meta_desc_resume`, `meta_desc_contact` |

삭제할 현행 키: `profile_*`(hero_로 대체), `sidebar_*` 전부(사이드바 제거), `intro_*`, `home_featured`, `home_intro_desc`, `portfolio_intro_*`, `portfolio_projects_*`, `portfolio_research_*`, `contact_card_*`, `contact_form_*`, `work_*_date`, `resume_pub*`, `resume_proj*`, `resume_intro_*`, 죽은 페이지의 `detail_*`와 `work_*`.

## 5. 작업 데이터 모델 (`assets/js/works-data.js`)

```js
window.WORKS = [
  {
    id: "ebpf",                     // 파일명, lang 키 prefix
    type: "project",                // "project" | "research"
    status: "completed",            // "completed" | "in-progress"
    date: "2026.02",                // YYYY.MM, in-progress면 null
    period: "2025.12 – 2026.02",    // 메타 스트립 Period (연구는 "2025.09 – present")
    updated: "2026.02",             // 연구만. "updated YYYY.MM" 표기. 프로젝트는 null
    featured: true,                 // Home Selected Projects 노출 (project만 의미)
    href: "project_ebpf.html",
    role: "Solo",                   // 메타 Role. 영어 단일
    stack: ["eBPF", "Go", "Linux"], // 메타 Stack. 카드 태그는 tags를 따로 둔다
    tags: ["eBPF", "Linux", "Go", "Observability"],   // 카드 태그, 최대 5
    illus: {                        // 08 문서. scenes/ebpf.js가 제공하는 함수 이름
      thumb: "thumb",               // 카드 썸네일 (필수)
      hero: "hero",                 // 상세 히어로 (없으면 thumb을 3:1로 재사용)
      alt: "Three eBPF probes on kernel tracepoints feeding a user-space collector"
    },
    keyfact: null,                  // 카드 desc 아래 한 줄 mono. 예: "8.4× faster · 2059 → 246 ms". 실측값만
    results: null,                  // 상세 Results 차트 spec (05 문서 6절). 없으면 validation 불릿
    evidence: [],                   // 실제 산출물 이미지. { src:"assets/img/rowscope-plot.png", alt, caption }
    artifacts: [
      { label: "Source", href: "https://github.com/...", kind: "code" },
      { label: "Report (PDF)", href: "assets/pdf/...", kind: "pdf" }
    ],
    prevNext: true                  // pager 포함 여부 (항상 true, 예약)
  },
  …
];
```

썸네일은 7개 모두 08 문서의 등각 장면이다(`illus.thumb` 필수). `keyfact`, `results`, `evidence`는 실제 값만. 초기값:

| id | keyfact | results (차트) | evidence (PNG) |
|---|---|---|---|
| ebpf | null (실측 확보 전) | null → validation 불릿 | 없음 |
| rowscope | "99.95% vs 0.4% hit rate · seq vs random" | line: `hit = 1 − stride·4/8192`, 실측 4점(99.95/87.49/49.98/0) | `rowscope.png` (실제 stride 플롯) |
| can | "6 signals · 64 bits · 0 overlap" | bits: `[10,19,21,3,1,10]` | `CAN.png` (LabVIEW 패널이면 유지, Phase 3 확인) |
| 5g_oran | null | null → validation 불릿 | 없음 (`oran_5g_system.png` 삭제) |
| opencl | "8.4× faster · 2059 → 246 ms" | bar: 2059 / 246 / 81 / 72 ms | `openCL.png` 내용 확인 후 결정 |
| dynamic_moh | null | null → findings | 없음 |
| pim_accel | null | null (Zipf skew vs speedup 자리 예약) | 없음 |

프리뷰의 카드 스파크라인(RowScope 라인, eBPF 히스토그램)은 폐기한다. 카드에는 썸네일 장면 + keyfact 한 줄만 둔다. 데이터 차트는 상세 Results에만.

## 6. 상세 본문 키 (`detail_<id>_*`)

05 문서의 템플릿 필드와 1:1. 프로젝트와 연구의 필드 집합이 다르다. 현행 키 중 유지/이동/삭제:

| 현행 | 처리 |
|---|---|
| `detail_<id>_title`, `_subtitle`, `_overview` | 유지. `_overview`는 프로젝트 "Problem" 또는 연구 "Motivation" 본문으로 |
| `detail_<id>_point1..3` | 프로젝트 "What I built" 불릿으로 유지 |
| `detail_<id>_arch_heading/body` | 유지 (도식 아래 설명) |
| `detail_<id>_pipeline_*` | 프로젝트 "How it works" flow 스텝. 연구는 "Approach" |
| `detail_<id>_validation_*` | 프로젝트 "Results" 불릿, 연구 "Current findings" |
| `detail_<id>_debug_*` | 프로젝트/연구 "What went wrong" (내용 있는 경우만 섹션 노출) |
| `detail_<id>_skills_*` | 삭제. 태그와 메타 Stack으로 대체. 이력서 Skills로 흡수 |
| `detail_<id>_artifacts_*`, `_artifact_*` | 삭제. works-data.artifacts로 이동 |
| (신규) `detail_<id>_fig_<name>` | 설명 도식 캡션. 08 문서 4절의 도식 이름과 1:1 (예: `detail_can_fig_frame`, `detail_can_fig_packing`, `detail_can_fig_ids`) |
| (신규) `detail_<id>_evidence<n>` | 증거 PNG 캡션 (출처 파일명, 측정 조건 포함) |
| `detail_<id>_role/timeline/stack` | 삭제. works-data로 이동 |
| `detail_overview_heading`, `detail_contribution_heading` 등 공통 | `detail_common_*`로 개명 |

RowScope 키 29개는 현재 `lang-data.js`에만 있다. JSON으로 옮기는 작업이 Phase 1의 첫 항목이다.

kr.json과 jp.json은 en.json과 키 집합이 정확히 같아야 한다. 영어 그대로인 키도 값을 복사해 넣는다(누락 검사가 단순해진다).

## 8. 검사 스크립트 (`scripts/check.mjs`)

실패 시 exit 1. 항목:
1. en/kr/jp 키 집합 동일.
2. 모든 HTML의 `data-lang` 키가 en.json에 존재.
3. en.json에 있는데 어느 HTML/JS에서도 참조하지 않는 키 목록 경고.
4. `lang-data.js`가 JSON에서 생성된 내용과 byte 단위로 동일.
5. works-data의 `href`, `hero`, `artifacts[].href`(로컬 경로)가 실제 파일로 존재.
6. works-data의 id마다 `detail_<id>_title`이 en.json에 존재.
7. 값에 "To be added", "Your Name", "Lorem", "TBD" 포함 시 실패.
8. 모든 HTML에 `<title>`, `<meta name="description">`, `og:title` 존재.

`package.json` 스크립트: `build` (lang-data 생성), `check`, `images`. 의존성 없음(Node 내장 모듈만). 커밋 전 `npm run build && npm run check`.
